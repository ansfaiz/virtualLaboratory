# P1.3 Published Assignment Editing

## Scope

Implemented constrained editing for published assignments through the existing `PUT /api/assignments/{id}` endpoint.

Allowed update fields remain:

- `title`
- `description`
- `starterCode`
- `dueDate`
- `maxScore`

Unchanged fields remain outside `AssignmentUpdateRequest` and are not modified by this flow:

- `languageId`
- `sectionIds`
- `status`
- `teacherId`

## Behavior

- Draft assignment update behavior is preserved: non-null request fields are applied as partial updates.
- Published assignments no longer fail with a blanket `403 FORBIDDEN`.
- Published assignment `maxScore` updates are checked against persisted graded submissions.
- A published assignment update is rejected with `409 CONFLICT` when any `GRADED` submission has `marks > request.maxScore`.
- Ungraded submissions and null marks do not block the update.

## Repository Check

Added the derived Spring Data repository method:

```java
boolean existsByAssignmentIdAndStatusAndMarksGreaterThan(
    Long assignmentId,
    Submission.Status status,
    Integer marks
);
```

`AssignmentService.update()` uses this method instead of loading all submissions.

## Explicit Non-Goals

This change does not add assignment creator ownership validation. Future authorization is expected to be allocation-based across Teacher, Subject, Batch, and Section.

This change does not introduce subject allocation, token blacklist persistence, Judge0, frontend changes, secrets externalization, or new due-date policies.
